# V38 Audit Logs: Testing Specification

## 1. Test Strategy
- Integration testing using Vitest and Supertest against REST API endpoints.
- Role-based authorization: Students and non-admin users must receive 403 Forbidden.
- Query filters: Entity filtering, action filtering, actor filtering, keyword search, and pagination.
- Tamper-proofing: Verification that direct POST/PUT/DELETE HTTP endpoints are absent (404 Not Found).
- In-flight event logging: Verification that events generated by other modules (e.g. V7 Department creation) appear immediately in the audit trail.

## 2. Test Cases Covered in `backend/tests/audit.test.ts`
- `GET /api/v1/audit-logs as Student`: 403 Forbidden.
- `GET /api/v1/audit-logs as Admin`: Retrieves paginated list of recorded events with metadata.
- `GET /api/v1/audit-logs?entity=DEPARTMENT`: Successfully filters logs by target entity.
- `GET /api/v1/audit-logs/:id`: Retrieves full details and JSON payload for specific log ID.
- `POST /api/v1/audit-logs`: Rejects manual entry creation with 404 Not Found.
